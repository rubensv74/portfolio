# Evolución visual — PULSE

## Objetivo

Esta pieza no pretende comparar una pantalla fea con otra bonita. Su objetivo es explicar cómo fue cambiando la forma de resolver el problema.

La evolución que interesa mostrar es funcional:

**información separada → resumen consolidado → selección útil → revisión dentro del mismo contexto**.

## Evidencia utilizada

La historia se apoya en decisiones documentadas en PULSE:

- cuatro indicadores principales para resumir el estado;
- análisis mediante heatmap y distribución por categoría;
- listado detallado asociado al contexto seleccionado;
- incorporación posterior de análisis por disciplina;
- necesidad de que las barras de disciplina actúen como filtro del listado;
- eliminación o reducción de elementos que ocupaban espacio sin aportar suficiente valor;
- construcción y validación por bloques;
- desarrollo posterior de un espacio específico de Punch Review.

No se representarán capacidades que no formen parte de PULSE.

## Narrativa

### Etapa 1 — Tener información

El punto de partida funcional es el acceso a muchos registros y distintos atributos.

El problema: una tabla puede contener toda la información necesaria y aun así no ayudar a conducir una revisión.

La pregunta principal del usuario sigue siendo: **¿por dónde empiezo?**

### Etapa 2 — Entender la situación

Se incorporan indicadores y distribuciones que permiten identificar rápidamente volumen y concentración del trabajo.

El objetivo deja de ser solo consultar registros y pasa a ser detectar dónde merece la pena profundizar.

### Etapa 3 — Convertir el análisis en acción

La selección deja de ser puramente visual. Elegir una disciplina o un área de análisis reduce el conjunto de punches que se está revisando.

La pregunta cambia a: **¿qué elementos concretos explican lo que estoy viendo?**

### Etapa 4 — Crear un espacio de revisión

El paso más maduro consiste en reunir contexto, cola de revisión, detalle y acciones en un espacio pensado para una sesión de trabajo.

La información deja de ser un dashboard que se observa y pasa a formar parte de un flujo de revisión.

## Qué cambia entre etapas

| Antes | Evolución |
|---|---|
| La tabla es el punto de entrada | El resumen orienta dónde mirar |
| Los gráficos describen | Las selecciones ayudan a filtrar |
| Resumen y detalle están más separados | El usuario mantiene el contexto al bajar al detalle |
| La pantalla acumula controles | Se priorizan los que ayudan a revisar |
| Cambios grandes son difíciles de validar | La pantalla se construye por bloques y se valida progresivamente |

## Regla visual

La comparación utilizará datos totalmente ficticios y nombres de proyectos inventados.

No se utilizarán mapas, localización geográfica, métricas de impacto inventadas ni ninguna funcionalidad añadida para hacer la composición más atractiva.

## Mensaje profesional

La pieza debe demostrar que el trabajo no consistió simplemente en diseñar gráficos. Consistió en ir acercando la interfaz al proceso real de decisión:

**ver → detectar → seleccionar → revisar → actuar**.
